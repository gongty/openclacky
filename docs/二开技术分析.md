**关键设计取舍：**
- **16 个核心工具** + `invoke_skill` 元工具 → 工具 schema 不膨胀，token 占用低
- **System prompt 永不变更** + **Insert-then-Compress** → 上下文压缩仍能命中 prompt cache
- **3 套消息格式适配器**（Anthropic / OpenAI / Bedrock）→ BYOK 任意 OpenAI-兼容 endpoint
- **Subagent fork** + **lite 模型路由** → 子任务用便宜模型，token 成本降一档
- **Skill 单文件（SKILL.md）** + 多层级目录优先级 → 用户可自定义、自演化、可加密分发

## 1. 项目概览

### 1.1 是什么

OpenClacky 是用 Ruby 写的命令行 / Web AI Agent，定位是 "最省 token 的开源 Claude Code 等价物"。MIT 协议，BYOK（带自己的 API Key），支持任意 OpenAI / Anthropic / Bedrock 兼容的模型端点。

入口三个可执行文件（`openclacky.gemspec` 的 `spec.executables`）：

| 命令 | 入口 | 说明 |
|---|---|---|
| `clacky` | `bin/clacky` | 主命令，开发者最常用 |
| `openclacky` | `bin/openclacky` | 同上别名 |
| `clarky` | `bin/clarky` | 同上别名 |

三个文件内容几乎相同，都是 4 行：`require "clacky"; Clacky::CLI.start(ARGV)`。

### 1.2 技术栈

| 维度 | 选型 | 备注 |
|---|---|---|
| 语言 | Ruby `>= 2.6.0`（推荐 3.1+） | gemspec 用 2.6 兼容旧系统 |
| HTTP 客户端 | `faraday >= 2.0, < 2.9` | 锁版本是为了兼容 Ruby 2.6 |
| CLI 框架 | `thor` | 子命令路由 |
| TUI | `tty-prompt` / `tty-screen` / `tty-markdown` / `pastel` / `rouge` | 自研 ui2 层封装 |
| Web 服务器 | `webrick`（stdlib） + `websocket` gem | 不引外部 web 框架（轻量） |
| 测试 | `rspec`、`climate_control` | |

**没有外部 LLM SDK** —— Anthropic / OpenAI / Bedrock 的 HTTP 协议都是自己手写，便于精细控制 cache_control、reasoning_content 等字段。

## 2. 启动流程：从 `bin/clacky` 到 Agent 跑起来

```
bin/clacky
  └─► Clacky::CLI.start(ARGV)               lib/clacky/cli.rb
        └─► 子命令分发（Thor）
              ├─► agent  ─► AgentRunner.run   # 默认子命令，CLI/TUI 交互
              │              └─► Clacky::Agent.new(...)
              │                    └─► Agent#run(input)
              └─► server ─► Server::HttpServer.new(port: 7070).start
                              ├─► WEBrick 主循环
                              ├─► SessionRegistry（懒加载）
                              └─► WebSocket handler /ws
```

`Clacky::CLI`（`lib/clacky/cli.rb`）的关键选项：

- `--mode <auto_approve|confirm_safes|confirm_all>` — 权限模式
- `--theme <hacker|minimal>` — TUI 主题
- `--model <preset>` — 模型
- `--message "..."` — 一次性 prompt 模式（不进交互）
- `--attach <id>` / `--continue` / `--list` — 会话管理
- `--json` — NDJSON 流式输出（脚本化集成）

CLI 启动时还会做 **sibling server discovery**（`cli.rb:77-79`）：如果同机已经有 `openclacky server` 在跑，自动把 `CLACKY_SERVER_HOST/PORT` 注入 env，让 skill 里调 `/api/*` 时不用重新指定。

## 3. Agent 核心循环

### 3.1 类结构

`lib/clacky/agent.rb` 是整个项目最重的文件（1300+ 行）。`Clacky::Agent` 类用 `include` 拆分成多个 mixin，分别在 `lib/clacky/agent/` 下：

```ruby
class Agent
  include MessageCompressorHelper   # 消息压缩
  include ToolExecutor              # 工具调度执行
  include CostTracker               # 成本统计
  include SessionSerializer         # 会话存盘 / 恢复
  include SkillManager              # Skill 调度、子 agent 派生
  include SystemPromptBuilder       # System prompt 构建
  include LlmCaller                 # 调 LLM、重试、容错
  include TimeMachine               # Undo / Redo / Tasks
  include MemoryUpdater             # 长期记忆刷盘
  include SkillEvolution            # Skill 自演化（运行后更新 SKILL.md）
  include SkillReflector            # Skill 反思
  include SkillAutoCreator          # 自动创建新 skill
end
```

> **二开提示**：这种 mixin 拆分是 Ruby 风格，但调用关系隐藏在多个文件里。建议先用 `grep -rn "def methodname" lib/clacky/agent/` 定位实现，再回头读 `agent.rb` 主流程。

### 3.2 主循环：think → act → observe

`Agent#run(input)`（`agent.rb:198-575`）是入口，简化版：

```ruby
def run(input)
  setup_iteration             # 注入 system prompt（首次）、读文件、附件处理
  loop do
    @iterations += 1
    response = think          # 调 LLM
    if response.tool_calls.empty?
      break                   # 终态
    end
    act(response)             # 执行所有 tool_call
    observe(results)          # 把 tool_result 写回 history
    flush_pending_injections  # 把延迟注入的 skill 内容塞入
    compress_if_needed        # 触发压缩
  end
  cleanup                     # 跑 skill_evolution / memory_update
end
```

三个核心阶段：

1. **`think`**（`agent.rb:367`） — 调 `LlmCaller#call_llm`，处理上游截断（`UpstreamTruncatedError`）时递归重试
2. **`act`**（`agent.rb:459`） — 经 `ToolExecutor#execute_tool` 调度，按权限模式询问用户、记录 redacted 参数
3. **`observe`**（`agent.rb:470`） — 把 tool result 作为 `role:"tool"`（OpenAI）/ `tool_result` block（Anthropic）追加到 `@history`

### 3.3 钩子系统 — 扩展点 #1

`@hooks = HookManager.new`，注册方式（`agent.rb:131`）：

```ruby
agent.add_hook(:on_start)        { |ctx| ... }
agent.add_hook(:on_iteration)    { |ctx| ... }
agent.add_hook(:before_tool_use) { |ctx| ... }
agent.add_hook(:after_tool_use)  { |ctx| ... }
agent.add_hook(:on_tool_error)   { |ctx| ... }
agent.add_hook(:on_complete)     { |ctx| ... }
```

**用法举例**：
- 想加自定义日志 / 审计 → `before_tool_use` + `after_tool_use`
- 想接入外部计费系统 → `on_complete` 读 `agent.total_cost`
- 想做工具黑名单（动态） → `before_tool_use` 里抛异常

### 3.4 上下文压缩 — Insert-then-Compress

README 提到的 "ultra-high cache hit rate" 主要靠这个机制（`agent.rb:590-640` + `agent/message_compressor.rb`）：

**核心思想**：
1. System prompt **永远不动**（包括 tool 定义）—— cache 不失效
2. 压缩时不是 "重写历史"，而是**追加一条压缩任务消息** + LLM 调用
3. LLM 调用结束后，**重组历史**为 `[system, 压缩摘要, 最近几轮]`
4. 下一次用户消息追加在后面，**压缩这一轮本身的输出**就被 cache 住了

伪代码：

```ruby
def compress_messages_if_needed
  return unless should_compress?  # 按 token 阈值判断

  prompt = build_compression_prompt(@history)  # "请把上面对话压缩为..."
  @history.append(role: "user", content: prompt, system_injected: true)

  summary = call_llm(@history)  # ← cache 命中，几乎免费

  @history = MessageHistory.new
  @history.append(@compressed_summaries.last)  # 摘要
  @history.append(recent_turns)                # 最近 N 轮（防丢上下文）
  @compression_level += 1
end
```

**双 cache marker**（`agent.rb:61`）：
- 第一轮：在最后一个 tool definition 上挂 `cache_control: { type: "ephemeral" }`
- 压缩轮：复用同一个 cache marker

这一套是 README 那张表里 "0.8-1.2× cost vs Claude Code 1.0×" 的关键来源。

### 3.5 Thinking-mode 自适应

`agent.rb:285-306`：如果 history 里 **任何** assistant 消息带 `reasoning_content` 字段（GPT-o1 / Claude thinking / DeepSeek-R1 等），就给所有 assistant 消息补 `reasoning_content: ""`，避免 thinking-mode provider 报参数缺失。**没有硬编码 provider 名字**，靠数据自检测 —— 二开加新模型时不用动这部分。

### 4.2 Base 类 API

`lib/clacky/tools/base.rb`：

```ruby
class MyTool < Clacky::Tools::Base
  self.tool_name        = "my_tool"
  self.tool_description = "Does X"
  self.tool_parameters  = {
    type: "object",
    properties: { arg: { type: "string" } },
    required: ["arg"]

  self.tool_category    = "custom"   # 可选

  def execute(arg:, working_dir:)
```

```ruby
agent.instance_variable_get(:@tool_registry).register(MyTool.new)
```

### 4.3 ToolRegistry — 名字解析

`lib/clacky/agent/tool_registry.rb` 的 `resolve(name)` 处理 LLM 调工具时的名字模糊匹配：

1. exact match
2. case-insensitive
3. alias table（~70 个内置别名，比如 `"read"` → `"file_reader"`, `"shell"` → `"terminal"`）
4. 连字符 ↔ 下划线归一化

**二开点**：要禁掉某些工具，用 `allowed_definitions(allowed_tools)` 过滤；要换工具的实现（比如把 `web_search` 换成自家搜索 API），换 register 的实例就行。

## 5. Skill 系统

### 5.1 SKILL.md 格式

YAML frontmatter + Markdown 正文。完整字段：

```yaml
---
name: skill-identifier              # 必填，唯一 ID
description: 触发时机说明            # 必填，决定 LLM 是否调用此 skill
disable-model-invocation: false     # true 则只能 /slash 手动调
user-invocable: true                # 是否允许 / 命令
allowed-tools: [Tool1, Tool2]       # 限制子 agent 可用工具
context: 4000                       # token budget hint
agent: coding|general|all           # 哪类 agent 可见
argument-hint: "subcmd | arg1"      # CLI 提示
hooks: ["on_complete"]              # 生命周期钩子
fork_agent: false                   # 关键：是否派生隔离子 agent
model: lite|standard|extended       # 子 agent 模型
forbidden_tools: [write, edit]      # 子 agent 黑名单工具
auto_summarize: true                # 子 agent 结束后自动摘要
---

# 正文 Markdown
...
```

### 5.2 加载优先级

`lib/clacky/skill_loader.rb` 的 `load_all()` 顺序加载，**后加载的覆盖前面**：

1. `:default` — gem 内置 `lib/clacky/default_skills/`
2. `:brand` — `~/.clacky/brand_skills/`（加密、License 验证）
3. `:global_clacky` — `~/.clacky/skills/`（用户全局）
4. `:project_clacky` — `<project>/.clacky/skills/`（项目级，**最高**）

**二开点**：fork 后想加新内置 skill → 直接往 `lib/clacky/default_skills/<name>/` 加个目录就行，不用改加载代码。

### 5.4 Skill "自演化" 的真相

README 说 "skills self-evolve" —— 在代码层面就是两件事：

1. `agent/skill_evolution.rb` — 每轮 `run` 结束后，根据执行结果调 LLM 决定是否更新 SKILL.md
2. `skill-creator` 的 **Quick Mode**（`default_skills/skill-creator/SKILL.md:30-68`）：
   - 用 `mode: "quick"` 触发
   - 不询问用户，直接基于 context 生成最小可用 SKILL.md
   - 保存到 `~/.clacky/skills/auto-<name>-<timestamp>/`
   - 立即跑 frontmatter validator

> **二开警告**：自演化会修改用户磁盘上的 skill 文件。如果你做 SaaS 化部署，这块要么关掉、要么沙箱化。

### 5.5 Subagent 派生：fork_agent

当 SKILL.md 里 `fork_agent: true`，调用流程：

```
invoke_skill 工具被调
  └─► InvokeSkill#execute (tools/invoke_skill.rb:32-70)
        ├─► skill.fork_agent? == true
        └─► agent.execute_skill_with_subagent(skill, task)
              ├─► fork_subagent(model:, forbidden_tools:)  # agent.rb:1129-1253
              │     ├─► Marshal.load(Marshal.dump(history))  # 深拷贝历史
              │     ├─► 新 Client（可选 lite 模型）
              │     └─► 新 Agent 实例（@is_subagent=true）
              ├─► subagent.run(task_input)  # 阻塞直到完成
              ├─► generate_subagent_summary
              ├─► 把摘要塞回父 agent history
              └─► total_cost += subagent_cost
```

**Cost 优化点**：`model: "lite"` 会从 `Providers.lite_model()` 拿到便宜模型（如 Haiku / DeepSeek）。父 agent 用 Sonnet，子任务用 Haiku，总 token 成本能再降一截。

## 6. 消息历史与上下文管理

### 6.1 MessageHistory 类

`lib/clacky/message_history.rb`。一条 message 是 Hash，关键字段：

```ruby
{
  role: "user|assistant|tool|system",
  content: "...",                  # 或 array of blocks（Anthropic 格式）
  tool_calls: [...],               # OpenAI 格式
  tool_call_id: "...",             # tool result
  # —— 以下都是内部字段，to_api() 时会被剔除 ——
  task_id: "...",
  created_at: "...",
  system_injected: false,          # 标记是否是注入的（压缩 prompt 等）
  session_context: {...},
  memory_update: {...},
  subagent_instructions: "...",
  subagent_result: {...},
  token_usage: {...},
  compressed_summary: "...",
  chunk_path: "...",               # 大文件分块存盘
  truncated: false,
  transient: false,                # 只在本轮内可见
  chunk_index: 0,
  chunk_count: 1,
  reasoning_content: ""            # thinking-mode 占位
}
```

**`to_api(force_reasoning_content_pad:)`**：去内部字段，按需补 `reasoning_content`，发给 LLM。

**`append(msg)`**：自动检测并丢弃悬挂的 `tool_calls`（防止 API 报 "tool_use without tool_result"）。

**`estimate_tokens`**：4 字符/token 近似 + CJK 调整。不调 tokenizer，纯估算，但够用。

### 6.2 三套 Message Format 适配器

`lib/clacky/message_format/{anthropic,openai,bedrock}.rb` 各实现：

```ruby
class MessageFormat::XXX
  def build_request_body(messages:, model:, tools:, max_tokens:, caching_enabled:)
  def parse_response(data) → { content:, tool_calls:, finish_reason:, usage: }
  def format_tool_results(response, tool_results, model:)
end
```

由 `Client` 根据 `Providers.api_type_for_model(...)` 选用。**二开加新 LLM 协议**（比如 Gemini、Cohere）就是写一个新适配器 + 在 `Providers` 注册 preset。

## 7. LLM Provider 抽象

### 7.1 19 个内置 Preset

`lib/clacky/providers.rb` 的 `PROVIDERS` 哈希包含（节选）：

- **Anthropic 系**：`claude`（直连）、`openrouter`、`clackyai`（Bedrock 代理）、`kimi-coding`（仿 Anthropic Messages）
- **OpenAI-兼容**：`deepseek-v4`、`minimax`、`kimi`、`glm`、`openai`、`mimo`
- **自家代理**：`openclacky`（统一代理，混合 Claude/DeepSeek 路由）

每个 preset 字段：

```ruby
{
  "name" => "Provider Name",
  "base_url" => "https://...",
  "api" => "anthropic-messages | openai-completions | bedrock",
  "default_model" => "...",
  "models" => [...],
  "capabilities" => { "vision" => true },
  "model_capabilities" => { "model-x" => { "vision" => false } },
  "model_api_overrides" => { /regex/ => "anthropic-messages" },
  "lite_models" => { "primary-model" => "lite-model" },     # subagent 用
  "fallback_models" => { "primary" => "fallback" },         # 503 时自动切
  "endpoint_variants" => [ { "base_url" => "..." } ]        # 区域/计费变体
}
```

### 7.2 BYOK 流程

1. 用户在 `/config` 填 `api_key` / `base_url` / `model`
2. `AgentConfig` 存为 `@models` 列表
3. `Client#initialize` 调 `Providers.resolve_provider(base_url:, api_key:)`
4. 不认识的 base_url → 看 `anthropic_format` 显式 flag → fallback
5. `Client` 按 `api` 字段路由到 `bedrock_connection` / `anthropic_connection` / `openai_connection`

**二开点**：自定义 provider 在 `providers.rb` 加一个 entry 即可，无需改其他文件。要把 ClackyAI 自家代理换成你自己的，改 `clackyai` entry 的 `base_url`。

## 8. Web 服务器与多会话

### 8.1 HttpServer

`lib/clacky/server/http_server.rb`（170KB，主类）：

- **框架**：WEBrick（Ruby 标准库）+ `websocket` gem
- **默认端口**：7070（`--port` / `--host` 可改）
- **路由**：
  - `GET /ws` → WebSocket 升级
  - `* /api/*` → JSON REST endpoints
  - `GET /*` → 静态文件（`lib/clacky/web/`）

### 8.2 多会话

`lib/clacky/server/session_registry.rb`：

- `SessionRegistry` 是会话状态的**唯一权威**（内存 + 磁盘元数据）
- 懒加载：`ensure(session_id)` 按需从磁盘恢复
- Mutex 保护，避免半构造态被读
- 24 小时空闲清理

会话磁盘格式由 `lib/clacky/agent/session_serializer.rb` 决定（JSON），跨 CLI / WebUI 互通 —— 终端会话开一半，浏览器接着聊不丢上下文。

### 8.3 WebSocket Event Loop

`@ws_clients[session_id] → [WebSocketConnection, ...]` —— 一个 session 可以被**多个浏览器 tab** 同时订阅，事件广播。

`lib/clacky/server/web_ui_controller.rb` 实现 `Clacky::UIInterface`，把 CLI 里 `show_user_message` / `show_tool_call` 等调用全部转成 WS event 推给前端。这意味着 **CLI 和 WebUI 共享同一个 Agent 实例的输出**，UI 是单向 view。

### 8.4 前端 SPA

`lib/clacky/web/` —— 纯 HTML/JS/CSS（**无打包工具**），文件直发：

- `index.html` — SPA 骨架
- `app.js` — chat 主循环
- `ws.js` + `ws-dispatcher.js` — WS 客户端
- `sessions.js` — 会话列表
- `skills.js` — skill 浏览器
- `settings.js` / `profile.js` — 配置

**二开**：要换前端框架（Vue/React）也行，把 `lib/clacky/web/` 整个换掉、保持 WS 协议即可。

## 14. 二开路上的坑

### 14.1 Ruby 版本兼容性

gemspec 写 `>= 2.6.0` 但实际功能 fully tested 在 3.1+。如果你只在 macOS 系统 Ruby 上跑（默认 2.6），会遇到一些 faraday / rubyzip / rouge 的边界问题。**建议直接用 `mise` 装 3.3**。

### 14.2 自演化 Skill 的副作用

`skill_evolution` 会**修改磁盘上的 SKILL.md**。如果你做企业部署：
- 关掉自演化（删 `include SkillEvolution` 那行）
- 或者把 SKILL.md 标记为 read-only

### 14.3 单进程多会话的内存

`SessionRegistry` 全部 sessions 留在 RAM。大量并发会话场景下要监控内存。生产环境考虑加 LRU 淘汰。

### 14.4 WEBrick 的并发模型

WEBrick 是每请求一线程，**没有连接池**。如果接入大量 WS 客户端 + IM webhook 高频回调，要考虑换 Puma 或 Falcon。

### 14.5 Tool name 冲突

`tool_registry` 没有命名空间。自定义工具如果撞名（比如你写一个 `search` 但已经有 `web_search` 别名指向 `search`），会被悄悄覆盖。建议用唯一前缀。

### 14.6 Brand Skills 加密

`~/.clacky/brand_skills/` 下的 `.enc` 文件用 BrandConfig 解密。如果你 fork 后想做自家加密分发，需要重写 `BrandConfig`（密钥源、license 校验逻辑都在那）。

### 14.7 Bedrock / Anthropic 的 tool_use 顺序

Bedrock 对 `tool_use` 后必须紧跟 `tool_result` 极其严格。`flush_pending_injections` 就是为了**延迟到 observe 之后**才注入 skill 内容、保持顺序合法。改这一段时务必跑 Bedrock 联调。

### 14.8 没用 Bundler 的 zeitwerk

代码里都是 `require_relative`，没有 autoload。加新文件要记得在父文件 require 一下，不然类找不到。
